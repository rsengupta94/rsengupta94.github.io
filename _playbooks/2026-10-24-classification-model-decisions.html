Classification Fine Tuning Series

Part 2: Model Decisions

Fine-tuning trains a model that already knows language to do one task. In text classification, the model reads a text and gives it one or more labels from a fixed list. After you prepare the data, you make seven decisions about the model and how it trains. This page explains each decision. Make the decisions in order, because an early decision can change a later one. You need the last decision only if the first training run misses rare labels.

01

Base model

The base model is the pretrained model that you start from. Your choice sets what the model already knows, how fast it trains, and how much memory it needs.

The decision

Which pretrained model do you start from?

You select the size, the base or chat version, and a general or a domain model. Start with the smallest model that passes the five checks in this section.

A classifier must give labels. Thus, fine-tuning removes the next-word output and adds a new output layer. The new output layer gives a confidence from 0 to 1 for each label. At first, the new layer has random weights, so its confidences are random.

What you select

  • SizeThe size is the number of weights. B means billion, so a 1B model has one billion weights. A larger model usually gets a better score, but it is slower and needs more memory.
  • Base or chat version DEFAULT: BASEThe base version has only pretraining. The chat version has extra training to follow instructions and to write answers. A classifier does not write answers, because the new output layer gives confidences. Thus, the chat training gives little benefit.
  • General or domainSome models learn from the text of one field, for example medical text. A domain model can do better than a general model of the same size.

Checks that the model must pass

  1. Is the context limit of the model at least as large as your length limit? The context limit is the largest number of tokens (parts of words) that the model can read. Your length limit is the largest number of tokens that you let it read from each text.
  2. Did the model learn from text in the language of your texts?
  3. Does the model load as a classifier in your library? In Hugging Face, the class is AutoModelForSequenceClassification.
  4. Does the model fit in the memory of your computer? Use the check below.
  5. Does the licence let you publish a model that you build from it?

Rule

Move to a larger model only if the smaller model stops improving.

Next, decide which weights of this model can change during training.

02

Training scope

The training scope is the set of weights that can change during training. The other weights are frozen, which means that they keep their pretrained values.

The decision

Which weights can change during training?

The options are the whole model, LoRA, the top layers, or the output layer only. Train the whole model if it fits in memory and is fast enough. If not, the limit that stops you selects the option.

How to decide

Find out what stops you from training the whole model. To find out, do a timing run. Train for a few minutes with the settings that you plan to use. The run shows how long training takes and how much memory it needs. It also finds errors early. Include the longest texts, because they need the most memory. Then use this tree.

Why LoRA does not save much timeTo make an update, the trainer calculates the changes from the output back through the layers. The LoRA blocks are in every layer, so this calculation must still go through the whole model. With top layers, the calculation stops near the top. It is the only option that saves a lot of time, and the cost is a lower score.
Why the output layer alone gets the lowest scoreThe pretrained model learned to predict the next word. It did not learn to summarize a whole text. If all other weights are frozen, the output layer can only use what the model already gives it. Use this option only for a quick first test.

Required step

If you freeze weights yourself, unlock the output layer again. In Hugging Face, the command that freezes all weights also freezes the new output layer. For all options, print the share of weights that learn, to make sure that the setting is correct.

Next, decide how you judge the model. You must do this before training, because the trainer uses the score to select the best checkpoint.

03

Headline score

The headline score is the one number that judges the model, and you report its value on the test set at the end. During training, the trainer measures it on the validation set. The trainer uses this validation score to select the best checkpoint.

The decision

Which number judges the model, and when does the model say “yes”?

You decide three things before training:

  1. The scoreF1 on the positive label, micro-F1 or macro-F1
  2. The barThe lowest recall that you accept for rare labels
  3. The cutoff ruleBest F1 or recall first (binary and multi-label tasks only)

Accuracy is the share of all answers that are correct. It is a simpler score, but it can hide a rare label. For example, if 2 of 100 emails are urgent, a model that always says “not urgent” gets 98% accuracy. But it finds no urgent emails.

Task types

The task type is set when you prepare the data. It decides how many scores you get.

  • Binary task. The text gets one of two labels, for example “urgent” or “not urgent”.
  • Multi-class task. The text gets exactly one label from three or more.
  • Multi-label task. The text can get any number of labels.

Part 1The score

A binary task has one label that you want to find. This is the positive label. Its F1 is the headline score.

A multi-class or multi-label task has a recall, a precision and an F1 for each label. To get one headline number, you combine them. There are two methods:

  • Micro-F1Add together the found cases, the missed cases and the false alarms of all labels. Then calculate one F1 from these totals. Each case counts the same, so the labels with many cases decide the score.
  • Macro-F1Calculate the F1 of each label. Then calculate the average of these values. Each label counts the same, so a rare label counts as much as a common label.

How to decide

  1. Is the task binary? If so, use the F1 on the positive label.
  2. Must the model do well on every label, including the rare labels? If so, use macro-F1.
  3. Do you need the most correct answers overall? If so, use micro-F1. In a multi-class task, micro-F1 is equal to accuracy.

Select the score before training, and do not change it later.

Part 2The bar

The bar is the lowest recall that you accept for each rare label. You can also set the highest number of false alarms that you accept. For example, “find at least 5 of every 6 urgent emails.”

Set the bar before you see any results, so that the results cannot change it.

Part 3The cutoff (binary and multi-label tasks)

The model gives a confidence from 0 to 1 for each label. The cutoff changes this confidence into a yes or a no. If the confidence is above the cutoff, the answer is “yes”. The default cutoff is 0.5.

In a multi-class task, the label with the highest confidence wins. Thus, there is no cutoff, and you can skip this part.

How to select the cutoff

The cutoff changes the answers of the model. It does not change the model. If you lower the cutoff, the model says “yes” more often. It finds more real cases, so recall increases. But it also gives more false alarms, so precision decreases. If you raise the cutoff, the opposite occurs.

During training, the trainer uses the default cutoff of 0.5. After training, select a better cutoff for each label on the validation set. You do not need to train again, because the model does not change. There are two rules:

  • Best F1Use the cutoff that gives the highest F1. This cutoff balances misses and false alarms. Use this rule if a miss and a false alarm cost the same.
  • Recall firstUse the highest cutoff that still meets the bar. A higher cutoff gives fewer false alarms. Thus, the highest cutoff meets the bar with the fewest false alarms. Use this rule if a miss costs more than a false alarm.

Required steps

  • Give the trainer the name of the headline score. If you do not, the trainer selects the best checkpoint by the loss on the validation set.
  • Measure the final model one time on the test set, at the cutoffs that you select. Report this score. The validation score is usually too high, because you used the validation set to select the best checkpoint and the cutoffs.
  • Report the recall and the precision of each label next to the headline score.
  • If you compare your model with a published result, also report the score that the published result uses.

Next, decide how the model learns. The first setting is the batch size, which sets how many examples go into each update.

04

Batch size

The batch size is the number of examples that the model reads before it makes one update to its weights.

The decision

How many examples go into each update?

You set two numbers, the batch per part and the parts per update. Together they give the effective batch. Aim for an effective batch of 16 to 32.

How the batch size changes training

  • Steady updatesA larger batch uses the average of more examples. Thus, one unusual example has less effect on the update. A small batch gives less steady updates.
  • Number of updatesWith the same data, a larger batch gives fewer updates in each epoch. For example, 10,000 examples in batches of 8 give 1,250 updates. In batches of 32, they give approximately 310 updates.
  • MemoryThe model processes all the examples in a batch at the same time. Thus, a larger batch or longer texts need more memory.

Options

  • Batch per part DEFAULT: 8This is the largest number of examples that fits in memory at your length limit. In Hugging Face, the setting is per_device_train_batch_size.
  • Parts per update DEFAULT: 1This is the number of parts that the model adds together for one update. A value of 1 means that the model does not use accumulation. In Hugging Face, the setting is gradient_accumulation_steps.

As a general rule, use an effective batch of 16 or 32 to fine-tune a classifier. The defaults give an effective batch of only 8 (8 × 1), which is below this range. With a batch per part of 8, 2 or 4 parts per update give 16 or 32.

How to decide

  1. What is the largest batch per part that fits in memory? Find this value with a timing run at your length limit.
  2. Which effective batch do you want? If the batch per part is smaller, use more parts per update to get that effective batch.
  3. How much training data do you have? If you have little data, use a smaller effective batch, so that each epoch has enough updates.

Next, decide how large each update is. This is the learning rate.

05

Learning rate

The learning rate sets how large each update to the weights is.

The decision

How large is each update?

You set the starting rate and how the rate changes during training. Start with 5e-5 for the whole model or the top layers, and between 1e-4 and 2e-4 for LoRA.

Options (values to start with)

  • Whole model or top layers DEFAULT: 5e-5The value 5e-5 means 0.00005.
  • LoRAStart between 1e-4 and 2e-4, which is 0.0001 to 0.0002.

If you train fewer weights, you can use a higher rate. If the model is larger, use a lower rate.

How to decide

The loss curve is a plot of the loss during training. There are two curves. The training loss comes from the training data. The validation loss comes from the validation set.

Start with the value for your training scope. Change the rate only if the loss curve shows a problem, or when you tune. To tune means to try several values and keep the best one. If you try other values, make each value about 3 times larger or smaller than the last one.

Loss curveWhat you seeWhat to do
The loss decreases and then becomes stable.This is correct. Keep the rate.
The loss increases suddenly, or it shows NaN.The rate is too high. Divide it by 3 or by 10.
The training loss and the validation loss both decrease slowly and stay high.The rate is too low. Multiply it by 3.
The loss stays flat from the first update.The cause is usually not the rate. If you froze weights yourself, make sure that the output layer is not frozen.

A larger batch usually needs a slightly higher rate. If you change the batch size a lot, examine the rate again.

Required step

Set the warm-up yourself, because the library default has no warm-up. In transformers 5, write warmup_steps=0.1. The setting warmup_ratio does not exist any more.

Next, decide how long the model trains. This is the number of epochs.

06

Epochs

An epoch is one full pass through the training data. The number of epochs is the number of times that the model sees each example.

The decision

How many passes through the training data?

You select a fixed number of epochs or early stopping. Start with the usual number for the size of your data, and always keep the best checkpoint.

Too few epochsThe model stops before it learns enough. At the end of training, the score on the validation set still increases.
Too many epochsThe model starts to memorize the training examples instead of the general patterns. This is called overfitting. The training loss continues to decrease, but the validation score stops increasing and then decreases. Each extra epoch also takes the time of a full pass.

Options

  • A fixed number DEFAULT: 3Train for exactly that number of epochs.
  • Early stoppingSet a maximum number of epochs. Training stops if the validation score does not improve for a set number of evaluations in a row. This number is the patience. If the patience is too small, one random decrease can stop training too early.

Typical numbers of epochs (general rules)

Training examplesUsual number of epochs
Fewer than about 1,0005 to 10
About 1,000 to 100,0002 to 5
More than about 100,0001 to 2

The total number of updates is what matters. A large dataset gives many updates in each epoch, so it needs fewer epochs. The whole model memorizes the data fastest. LoRA and top layers usually need a few more epochs. The validation score after the first run gives the final answer.

How to decide

  1. How many training examples do you have? Start from the usual range for that number.
  2. How long does one epoch take? A timing run tells you. This time sets the maximum number of epochs that you have time for.
  3. After the first run, did the validation score still increase at the end? If so, add epochs. Did the score reach its peak early? If so, use fewer epochs or early stopping.

Then set a maximum number of epochs. If each epoch is slow, add early stopping.

Required steps

  • Turn on “keep the best checkpoint”. It is off by default, so the trainer keeps the last checkpoint, which is not always the best.
  • Evaluate, save and log (record the scores) at the same interval, about 10 to 20 times in each run. The best checkpoint works only if the evaluations and the saves match. The interval is a number of updates. If you change the batch size, set the interval again.
  • Keep only the best checkpoint and the latest checkpoint (save_total_limit=2). By default, the library keeps all checkpoints. Each checkpoint holds the weights and the optimizer state (extra numbers that the trainer keeps for each weight), so it is large.

After the first run, examine the rare labels. The last decision is necessary only if they miss the bar.

07

Loss

The loss shows how wrong the answers of the model are. By default, a mistake on a rare label costs the same as a mistake on a common label.

The decision

Must mistakes on rare labels cost more?

Start with the standard loss. Change it only if the rare labels miss the bar after you select new cutoffs. In a multi-class task, there are no cutoffs, so check the bar directly after training. The options are weights for rare labels or a special loss.

Imbalance means that some labels have many more examples than others. The model then learns to prefer the common labels, and it gives low confidences to rare labels. A lower cutoff for a rare label can correct some of this, and it needs no new training. Thus, select the cutoffs before you change the loss.

Options

  • Standard loss DEFAULTThe library selects it from the task type. It is a form of cross-entropy.
  • WeightsA mistake on a rare label counts more. Full weights follow how rare the label is. Gentle weights are the square root of the full weights. Capped weights never go above a limit that you set.
  • Focal lossIt makes training focus on the difficult examples. It needs custom code and adds settings to tune.
  • Asymmetric loss (multi-label)It makes the penalty smaller for the many easy “no” answers. It needs custom code and adds settings to tune.

How to decide

Each change means that you must train again. Thus, go up one step at a time, and only while the rare labels do not meet the bar:

  1. Use gentle weights. Cap any label whose weight is much larger than the others.
  2. Use full weights.
  3. Use a special loss.

When to keep a change

Select new cutoffs after each change. Keep the change only if these two conditions are true:

  • The recall of the rare labels increased on the validation set.
  • The precision did not decrease too much.

Compare each label, and the macro-F1, with the run without weights. If no change meets the bar, keep the best run and record the gap.

+Fixes

If a run fails

Try these fixes in order

If the run is out of memory
  1. Use a smaller batch with accumulation.
  2. Calculate some values again instead of keeping them (gradient checkpointing). It is not related to the checkpoints that the trainer saves. The run uses less memory but is about 20% slower.
  3. Use a shorter length limit, or a smaller training scope.
If the run is too slow
  1. Use half-size numbers (bf16, or fp16 on older GPUs). These numbers use 16 bits instead of 32 bits, so they need less memory and calculate faster. Use them only if your GPU supports them directly. Some GPUs only imitate them, and then the run is not faster.
  2. Group the texts by length, so that there is less padding (empty tokens that fill short texts).
  3. Train fewer weights, or use a faster GPU.
If the model overfits (memorizes the training data), even with the best checkpoint
  1. Use fewer epochs, or early stopping.
  2. Add weight decay, which pulls the weights toward zero. The library default is 0, and common values are 0.01 to 0.1.
  3. Increase the dropout. This model setting turns off random parts of the model during training. Usually, you keep its default.
✓Always

Required steps

These steps need no decision. Each step is one line of code.

  • Use a fixed version of the model, so that you can repeat the run. Models on Hugging Face can change, and each version has an ID.
  • When you load the model, give it the number of labels and the task type. Also give it the names of the labels in a fixed order. The position of each name sets the number of that label, so keep the same order in training and in use. If you do not give these settings, the model uses two labels with the names LABEL_0 and LABEL_1.
  • Short texts in a batch get extra tokens to fill the empty places. These are padding tokens. Copy the ID of the padding token into the model. If you do not, the model does not accept batches larger than 1.
  • The seed is a number that sets the random numbers of a run. Set it immediately before you load the model. Then the new output layer starts in the same way in every run.
  • Remove all extra columns, for example IDs and metadata, before you change the text into tokens. The trainer cannot use them, and they can stop the run.

Glossary

This list explains the technical words on this page.

Example
One item in the data. It has a text and the correct label for that text.
Label
The answer that the model must give for a text, for example “billing”.
Case
An example that really has the label. Recall counts the cases that the model finds.
Task type
Binary (one of two labels), multi-class (exactly one label from three or more), or multi-label (any number of labels).
Training set
The examples that the model learns from.
Validation set
A set of examples that the model does not learn from. You use it to measure the model and to tune your choices.
Test set
Examples that you use one time, at the end, to measure the final model. This gives an honest final score.
Weight
One of the numbers inside the model. Training changes the weights. Another name for a weight is a parameter.
Layer
One stage of the model. A model is a stack of layers, and the text goes up through them.
Pretraining
The first training of the model. The model read a very large amount of text and learned to predict the next word.
Output layer
The top layer of the classifier. It gives a confidence for each label.
Confidence
A number from 0 to 1 that the model gives for each label.
Cutoff
The confidence above which a label counts as “yes”.
Bar
The lowest recall that you accept for each rare label. You set it before you see any results.
Batch
A small group of training examples. The model reads one batch before each update.
Loss
A number that shows how wrong the model is. Training changes the weights to make the loss smaller.
Update
One change to the weights. The model makes one update after each batch of examples.
Step
The Hugging Face name for one update. It is in setting names such as warmup_steps.
Epoch
One full pass through all the training data.
Evaluation
A measurement of the model on the validation set, at a fixed interval during training.
Loss curve
A plot of the loss over time. The training loss comes from the training data, and the validation loss from the validation set.
Checkpoint
A copy of the model that is saved during training.
GPU
A chip that does many calculations at the same time. Training runs on it, and its memory limits the size of the model and of the batch.
Timing run
A training run of a few minutes with the settings that you plan to use. It shows how long training takes and how much memory it needs.
Trainer
The part of Hugging Face transformers, a free code library, that runs the training loop.

Parts marked “Illustration” use made-up numbers. Setting names in code font come from Hugging Face transformers 5.
