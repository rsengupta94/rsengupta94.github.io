Classification Fine Tuning Series

Part 1: Data Decisions

Before you train a model to sort text into labels, you must make twelve decisions about your data. This page explains each decision in plain words. Make them in order, because an early decision can change a later one.

A

What is the task?

01What is the task?

Input

The input is what the model reads. The label is the answer that the model must give.

Rule

A column goes into the input only if both statements are true:

  1. It is always there when the model is used.
  2. It does not give away the answer. For example, a field that a person fills in at the same time as the label.
02What is the task?

Target and task type

The target is the column that holds the label. The task type tells how many labels one example can have.

How to decide

Count the labels on each example.

  1. Always exactly one label: binary if the list has two labels. Multi-class if the list has more.
  2. Sometimes more than one label: multi-label.

Rule

Keep the label list fixed. Use one spelling for each label. If not, “Cancer” and “cancer ” become two different labels.

ExampleIn the research-grant dataset, the target is the health-category column. It has 21 labels. About 20% of grants have more than one label, so the task is multi-label.

03What is the task?

Label set

Make sure that each label has enough examples. A rare label is hard to learn and hard to measure.

Hard to learnThe model learns a label from its training examples. With few examples, it learns the label badly.
Hard to measureYou measure a label on its test examples. With few examples, one mistake changes the score a lot.

Options

  • Keep all DEFAULTReport the score of each rare label. Make no claims about it.
  • MergeJoin two labels that mean almost the same thing.
  • DropRemove the label. The model can then never give it.
  • “Other”Put all rare labels into one bucket.

How to decide

Ask these questions for each rare label:

  1. User need. Do the users need this label?
  2. Cost of a miss. Is the label important, like a rare disease or fraud? Then keep it, however rare it is.
  3. Freedom to change. Must you keep the exact list? The labelling system, its license or another system can require it.
  4. Overlap. Does the label mean almost the same thing as another label?
Checks to run
  1. Count per label. Count the examples for each label in the training, validation and test sets. Sort from the rarest. This shows which labels are at risk.
  2. Noise check. For each rare label, calculate 100 ÷ n. Compare the result with the size of difference that you want to claim.
B

Can you trust it?

04Can you trust it?Short note

Label quality

People made the labels, and people make mistakes. The model learns the mistakes too.

Find out who made the labels, under which rules, and how consistent they are. Some “model errors” are really label errors. The default is to accept the labels. Fix clear errors in the training set only.

05Can you trust it?

Shortcuts

A shortcut is a clue that goes with a label but is not the reason for it. The model can learn the clue instead of the reason.

The key question

Is the clue a real signal, or something left over from how people collected the data?

✓ Real signal: keep itThe clue appears in real inputs, in the same way.
✕ Leftover: remove itA template, an email signature, or a label word that got into the text.

Options

  • Leave it in DEFAULTTrain on the text as it is.
  • Mask the clueReplace the clue with a neutral placeholder.
  • Drop the rowsRemove the rows that contain the clue.

How to decide

  1. Origin. Did the clue come from the real world, or from how people collected the data?
  2. Real use. Will the clue appear in real inputs, in the same way?
  3. Reliance. Does the model still do well on examples without the clue?
Checks to run
  1. Top words per label from a keyword model. A keyword model looks only at which words appear. It gives each word a weight for each label. Print the words with the highest weights for each label, and read them. Medical words are real reasons. Names, places and template phrases are possible shortcuts. tumouroncologychemotherapyCRUK ← suspect Illustration
  2. Count a suspect clue. Count how often it appears with each label, and how often with other labels.
  3. Score with and without the clue. Score the examples that contain it and the examples that do not. A large gap shows that the model depends on the clue.
  4. Read a sample per label. Look for repeated phrases or templates.
06Can you trust it?Short note

Match to real use

If real inputs differ from your data, the test score may not hold.

Real inputs can come from a later period or from new sources. They can also have a different mix of labels.

C

Clean

07Clean

Rows to drop

Find the broken rows. Drop them or fix them. Clean as little as possible.

Clean as little as possible

Do not change all text to lowercase. Do not remove punctuation or numbers. Models like this one use them as clues. Remove only what is broken.

Extra rule for the test set

Drop a test row only if it is broken. Never drop a test row because it is hard. Report each row that you drop. If not, the score looks better than it is.

Options

  • Keep DEFAULTLeave the row as it is.
  • DropRemove the row.
  • FixRepair the formatting, or correct the label spelling.

How to decide

  1. Usable. Does the row have an input and a valid label?
  2. Real use. Will real inputs look like this row? If real inputs can be short or untidy, keep such rows. The model must handle them.
  3. Fixable. Can you repair the row instead of dropping it?
  4. Which set. You can clean training rows freely. Test rows follow the stricter rule.
Checks to run
  1. Missing values in each column.
  2. The 20 shortest texts. Placeholders show up here.
  3. The most repeated texts. Placeholders and templates repeat.
  4. Odd characters: HTML tags, broken characters like â€™, long runs of symbols.
  5. Each label value and its count. This finds wrong spellings and values that are not in the list. For multi-label, also count the labels on each example. Flag examples above the allowed maximum.
  6. A cleaning report. Print the number of rows after each step, so that no step removes too much without notice.
08Clean

Duplicates

A duplicate is the same example in more than one row. Remove duplicates before you split the data.

Why it matters

  1. Leakage. A copy in the training set and its twin in the test set make the score too high.
  2. Extra weight. A repeated row counts many times in training, so the model leans toward it.
  3. Mixed signals. Conflicting copies give two answers for one input. They also show how consistent the labels are.

Options

KindOptions
Exact copiesKeep one DEFAULT
Conflicting copiesDrop all copies DEFAULT · keep one · combine their labels (multi-label only)
Near-copiesKeep all · keep one · put them in the same set (see 9–10)

Order

  1. Remove duplicates
  2. Split the data
  3. Check that no text is in two sets

How to decide

  1. Kind. Is it an exact copy, a conflicting copy or a near-copy?
  2. Where. Are the copies only in the training set (extra weight)? Or are they in two sets (leakage)? Always fix leakage.
  3. Conflicts. Is one label clearly correct? In multi-label, if both labels look valid, combine them. If you cannot tell, drop all copies.
  4. Near-copies. Are they the same example, for example a renewal? Then treat them as duplicates. If they only share a topic, keep both rows.
Checks to run
  1. Count the exact copies.
  2. Count the conflicting copies. This also gives a rough measure of label noise.
  3. Search for near-copies. Score each pair of texts by the words that they share. Read the pairs from the most similar down. Find the point where “same example” stops.
  4. Check the overlap after the split. No text, and no near-copy, must be in more than one set.
D

Split

09–10Split

Test and validation sets

The validation set is the practice exam. The test set is the final exam. Use the test set one time only, at the end.

Rules

  • Score the test set one time, at the end. Never use it to make a decision.
  • The validation set must look like the test set: the same period, the same sources, the same mix of labels.
  • Both sets must look like real use.
  • Both sets need enough examples of each label to measure it (see the noise check in 3).
  • Keep related rows together. Rows from the same person, customer or document go into the same set. Near-copies do too. If not, the model recognises what it already saw, and the score is too high.

How to split

  • Official splitIf the dataset comes with one, use it. Your score can then be compared with published results.
  • RandomShuffle the rows and cut. Simple.
  • StratifiedEach set gets the same share of each label. Use it when some labels are rare. For multi-label, it needs an add-on library.
  • By timeTrain on older data. Test on the newest data. Use it when the model will meet future data.
  • By groupAll rows from one person, customer or document go into one set. Use it when real use brings new groups.
  • SizesCommon splits are 70/10/20 and 80/10/10. Larger exam sets give steadier scores, but leave less for training.

How to decide: the test set

  1. Comparison. Must you compare with published numbers? Then use the official split.
  2. Real use. If not, split the way real use works. Future data: split by time. New groups: split by group. Neither: use a stratified split.

How to decide: the validation set

  1. Same method as the test set. If the test set is the newest period, take the validation set from the newest period in the training data.
  2. Size. Make it large enough to hold enough rare-label examples to set a cutoff for each label.
E

Shape for training

11Shape for training

Length

The model reads only a fixed number of tokens. It does not see the text after that limit.

A longer limitThe model sees more of each text. Training is slower and needs more memory.
A shorter limitTraining is faster. The part of the text that decides the label can be cut.

Options

  • Longest training text DEFAULTNothing is cut. One very long text makes each batch slow.
  • A percentile (95th–99th)Almost all texts fit. Only the longest few are cut.
  • A fixed limitSet by your compute budget, or to match a model that you compare against.
  • What to cutThe end DEFAULT, or keep the start and the end.

How to decide

  1. Lengths. How long are the typical text and the longest text? Count with the model's own tokenizer, because models count differently.
  2. Share cut. What share of the texts does each possible limit cut?
  3. Where the answer sits. Is the deciding text at the start, the middle or the end? If it is early, cutting the end loses little.
  4. Cost. Can you pay for the training time at that length?
  5. Comparison. Does a model that you compare against use a fixed limit?

Then test two limits on the validation set. If the scores are almost the same, use the shorter limit.

12Shape for training

Imbalance

Some labels have many more examples than others. The model learns to prefer the common labels.

Each training example moves the model a little. Common labels move it much more often. So the model gives rare labels low confidence, even when they are correct.

Options (training set only)

  • Do nothing DEFAULTTrain on the data as it is. Judge the model with the score of each label, not with overall accuracy.
  • Class weightsA mistake on a rare label counts more in training.
  • OversampleRepeat the rare examples in training.
  • UndersampleRemove common examples until the labels are balanced. Single-label tasks only. It throws data away.

The validation set and the test set always keep the real mix.

The cutoff: a fix after training

The model gives each label a confidence from 0 to 1. The cutoff is the confidence above which the label counts as “yes”. The cutoff works differently for each task type:

Task typeHow the model decidesCutoff
BinaryOne confidence: “how likely is this spam?”✓One cutoff. Lower it to find more of the rare class.
Multi-labelOne confidence for each label. Each label is judged alone.✓One cutoff for each label.
Multi-classThe confidences add up to 1. The highest one wins.✕No cutoff. The highest confidence always wins.

How to decide

  1. Ratio. How many times larger is the largest label than the smallest label?
  2. Stakes. Does a missed rare label matter for the job?
  3. Task type. For binary or multi-label, try the cutoff first. Multi-class has no cutoff, so class weights or oversampling are the main tools.

Train one time without weights. On the validation set, check the recall of each label: the share of its real cases that the model finds. Add weights only if the model still misses rare labels. Weights and a low cutoff push in the same direction. Together, they can cause too many false alarms.

✓Always

Rules for every dataset

  • Never change the raw file. Use a script that writes a new file. Print the number of rows after each step.
  • Pin the data version, as you pin the model version.
  • Look at the data before you fill in the settings.
  • Do not look at the test labels until the final score. Use the test set only to check the format and the overlap with training.
  • Tune all choices on the validation set: checkpoints, cutoffs and baseline prompts.
  • Apply the same rules to baselines. Examples that you show to a prompted model come from the training set only.
  • Take random samples. Never take “the first N rows”, because files are often sorted.
  • Prepare new inputs in the same way as the training inputs.
